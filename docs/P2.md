2. Install iOS Build Support and compatible AR Foundation/ARKit packages. Enable ARKit under the **iOS** XR Plug-in Management settings; installing a package alone does not enable its provider. Set the camera usage description and review XR Project Validation. Use minimum OS/settings supported by the selected Editor, packages, and device. 3. For the planned URP setup, configure the renderer actually selected for the device with `ARBackgroundRendererFeature`. Check quality-level renderer overrides if the camera background is missing. 4. Configure one AR Session, an XR Origin with its AR camera components, plane/raycast/anchor managers as needed, and horizontal plane placement. Include the intended startup scene in the iOS build. Confirm the camera feed on the real phone before adding drawing features.

6. Commit assets with their `.meta` files, package manifest/lock file, and project settings. Exclude generated Unity caches and Xcode output. Use text serialization and visible meta files; configure UnityYAMLMerge separately from any Git LFS binary rules.

### 4.2 Keep the first shared contract small

`MVP_PLAN.md` section 2.4 is an **API design sketch, not copy-paste-ready C#**. It omits constructors, equality/hash implementations, abstract overrides, and method bodies. Day 0 must produce a compiling subset, not treat the entire sketch as completed in two hours.

For P2 agree only these seams first:

- **Board/model:** line endpoints, circle center/radius, stable IDs, one default layer, fixed default 2x2 grid, current style, minimum sizes.
- **Editor session:** active tool, cursor validity, preview, pointer Down/Move/Up/Cancel, add-shape commands, Undo/Redo, model/state/preview change events.
- **Board adapter:** placement state, screen-to-board projection, board-to-screen projection for snap distances, reset/re-place.
- **Input/UI:** who captures a pointer, how toolbar clicks are excluded from drawing, how an interrupted action cancels, and which controls are enabled.

Define constructors and deep-copy rules for command snapshots; keep transient previews outside saved/model geometry. No lesson controller or persistence implementation is required to compile the P2 scene. Disabled future controls must tolerate those services being absent.

Prefer explicit tool factories for the small P2 tool set. If using the MVP's attribute/reflection discovery, preserve reflected classes/constructors for the iOS player and verify registration in the device build. Editor success alone is insufficient; see [Unity's managed code stripping guidance](https://docs.unity3d.com/6000.0/Documentation/Manual/managed-code-stripping.html).

### 4.3 Coordinate and touch contract

The model uses the MVP's normalized board coordinates: `(0,0)` at the chosen bottom-left corner, `(1,1)` at the opposite corner. A square board of proposed side `s = 0.40 m` may map a model point `(u,v)` to local `(s*(u-0.5), 0, s*(v-0.5))`. Document the board orientation chosen at placement. Keep the AR pose in the board adapter; geometry does not contain world positions.

**Before placement:** raycast against a detected horizontal plane for placement. **After placement:** intersect the camera ray with the placed board plane and transform into that board's local coordinates; reject points outside its bounds. Do not draw by repeatedly raycasting unrelated detected planes. Reject near-parallel rays and invalid/behind-camera projections.

Snap candidates are compared in **screen space** with a documented, device-tested pixel tolerance. A single global pixels-to-board conversion is inaccurate on a perspective board. Project candidates to screen coordinates, choose a valid nearby candidate, then commit its exact board coordinates. Test the corners as well as the center.

D and C agree on the input backend and its matching UI event module. Capture one pointer ID for a gesture. Ignore gestures starting on UI, additional fingers, and stale events. Decide and implement this policy consistently: leaving the board or entering the control panel cancels a drawing gesture; focus loss, re-placement, tool changes, and unusable AR tracking also cancel. Resuming requires a new pointer Down.

For the first integration, use **drag-to-draw**: Line = press endpoint, drag preview, release endpoint; Circle = press center, drag radius, release. Do not implement click-click, drag, and toolbar synthesis simultaneously before this works. The quick-menu point/click actions may stay disabled in P2. If enabled, implement and test the MVP's explicit point-placement mode so placing a snap point never also draws a shape. A physical drag and a synthetic toolbar click must not double-commit one action.

### 4.4 Integrate one real path

```text
Touch/mouse -> board projection -> real EditorSession -> command -> Board
UI buttons ---------------------> real EditorSession               |
                                                     BoardChanged -> BoardView
                                                     StateChanged -> UI state
                                                     PreviewChanged -> cursor/preview rendering
```

A and C compose the same real engine, UI, and input prefabs in `Main.unity` and `Flat.unity`; the board adapter differs. `Flat.unity` uses a flat camera/board and does not require AR availability. One composition root owns service registration; register before consumers subscribe, fail clearly on duplicates/missing required providers, and unsubscribe/reset on teardown. Re-entering Play Mode must not retain a stale static service or duplicate event subscription.

Integration sequence:

1. Empty board and real session in `Flat.unity`; prove one line changes the model and renderer.
2. Add Circle, basic snapping, then Undo/Redo and their UI states.
3. Connect the same path to the placed board in `Main.unity`; remove mock providers from this build.
4. Build/install; run section 6 on the phone. A working Editor scene is an intermediate gate.
5. Add the star fixture or Stamps only after the core path works. Provide an explicit way to reset to an empty board, so the fixture cannot obscure what the user actually drew.

`BoardChanged` rebuilds committed geometry; `PreviewChanged` refreshes transient feedback without adding history. Start with a bounded renderer that handles the small demo reliably; full mesh batching and the 300-shape stress target belong to later profiling.

### 6.1 Focused automated checks (B, with A/D fixtures)

Use EditMode tests for geometry and session behavior that can fail independently of AR. Run against the same commit used for the phone build. Preserve test output; a planned test name is not a passing test.

- Add a Line/Circle with known coordinates; reject non-finite values and minimum-length/radius violations.
